# Phase 2: local progression, Implementation Plan

> Written 2026-11-09 for branch `v2-p2` (cut from `v2-app-store` at 0a62e3a). James chose "A" at 15:22 ET and gave full authority on 2026-11-06, so every ruling below is Claude's call, logged, and changeable.

**Goal:** A new player meets one card that asks what brought them here and lands in a lesson; a returning player sees one path with the next node lit, three daily quests with a chest, a recap that lists the cards they missed and lets them fix them, says what unlocks next and what it needs, a wrong answer says when the card comes back, and a profile page shows rank, days, accuracy per world and achievements. All local and offline. The v1 save migrates to a v2 event-log save with nothing lost.

**Architecture:** Pure logic in `src/lib` (tested in vitest), thin React over it. One save, versioned: `passionate-learning:v2`. The v1 key is read once, migrated, and kept as `passionate-learning:v1-backup`. No network, no accounts (P3).

**Tech Stack:** unchanged from P1 (Next 16 static export, React 19, vitest 4, Playwright 1.63, Capacitor 8, ts-fsrs 4.7).

**Spec:** `docs/superpowers/specs/2026-11-06-app-store-v2-design.md`, phase P2, audit rows 1, 2, 4, 5, 10, 12, 13, and "Changed after the red team" item 2 (save v2 is an event log; v1 XP imported once, capped, flagged unverified, never counts toward leagues; FSRS stays client-owned).

## Rulings (made while planning)

- **R1 Storage key.** v2 lives under a NEW key, `passionate-learning:v2`. The v1 payload is copied to `passionate-learning:v1-backup` and the old key removed only after the v2 write reads back equal. A v2 save already present always wins; v1 is never re-imported over it. Reset progress clears the backup too, so Reset still means reset.
- **R2 Imported XP loses nothing locally.** The local `xp` keeps the player's full v1 XP so their rank never drops. The cap the red team asked for is recorded as `imported = { xp, cap, unverified: true }` where `cap = sum(cards.seen) * 30 + sum(units.rounds) * 35` (30 is the most one card can pay, 35 the most a round adds on top). P3's server credits `min(xp, cap)` and never to leagues.
- **R3 FSRS short-term steps off.** `enable_short_term: false` so a wrong answer is scheduled for tomorrow, not 1 minute away. With the steps on, "you'll see this again Thursday" would be false for almost every wrong answer. The new "Fix your mistakes" pass is the immediate retry. Fuzz stays, but is seeded per card and reps so the date the drawer shows is the date the save stores.
- **R4 Quests.** The spec's third quest is "play a daily game"; no daily game exists until P5. P2 ships Finish 1 round, Clear a review, Play a second round. P5 swaps the third. Floors: round one counts as the whole day (no streak, a missed day resets nothing), and "Clear a review" is waived when nothing was due, so a new player can always reach the chest. The chest pays 5 tokens, once a day.
- **R5 Profile leaves out league history.** Leagues are P4. A section with nothing in it would be a placeholder, so it is not there.
- **R6 Events.** The event log is append-only: `{ id, type: "round" | "fix", unit, cards, correct, durationMs, clientTs }`. `flushed` counts events already sent (0 until P3). No compaction in P2 (about 250 bytes an event; a daily player writes a few hundred a year).
- **R7 Home.** Fresh save: Home is the onboarding card alone. Otherwise: continue card, guide, Up next, today's quests with the chest, the path (cleared nodes folded, the lit node, three ahead), and links to Profile and All worlds. The nine-world grid moves to `/worlds/`.

## Review Focus

1. **Migration safety.** A v1 save of any shape (full, minimal `{v:1}`, junk fields, v2 already present, corrupt v2 with a v1 backup) must produce a valid v2 with progress intact, and must never overwrite a v2 save. Pinned in Task 1 with a real v1 fixture generated by the Phase 1 code.
2. **Fix pass must not touch unit progress.** It changes card memory and the review quest only. Pinned in Task 3.
3. **The drawer's date equals the stored date.** Pinned in Task 4.
4. **A fresh save at every viewport shows the onboarding card, and one tap reaches a card.** Pinned in Task 5.
